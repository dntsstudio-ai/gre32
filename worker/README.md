# Бэкенд приёма платежей (Cloudflare Worker)

Бесплатный "воркер" в облаке Cloudflare для покупки Старс за деньги без
подключённого платёжного провайдера (Robokassa отклонила заявку на
магазин) — **DIY-схема через СБП по номеру телефона**:

1. Покупатель на сайте выбирает пакет Старс и вводит почту.
2. Worker создаёт заказ с уникальной "до копейки" суммой (например, не
   100.00 ₽, а 100.37 ₽ — случайные копейки добавляются специально) и
   показывает покупателю номер телефона/банк/получателя, куда перевести
   именно эту сумму по СБП — как обычный перевод другу.
3. На телефоне-приёмнике (куда приходят деньги) установлено приложение
   типа **MacroDroid**, которое при получении SMS от банка о зачислении
   пересылает текст SMS на Worker.
4. Worker находит в тексте сумму, ищет заказ с такой же суммой, создаёт
   одноразовый промокод в коллекции `promoCodes` (та же, что использует
   кнопка "Активировать промокод" в магазине) и отправляет код письмом
   через EmailJS.
5. Покупатель вводит код на сайте — Старс начисляются через уже
   существующую систему промокодов.

Если в будущем какой-то провайдер всё же подключат — `robokassa.js` и
связанные маршруты в `index.js` оставлены как рабочая заготовка (тот же
принцип "промокод письмом", только подпись провайдера вместо SMS), но
сейчас с сайта используется только DIY-схема.

## Разово: установка и вход

```bash
cd worker
npm install -g wrangler   # если ещё не установлен
wrangler login            # откроет браузер для входа в Cloudflare (бесплатный аккаунт подходит)
```

## Шаблон письма в EmailJS — создать один раз

В личном кабинете EmailJS (emailjs.com) создать новый шаблон, например с
id `template_starscode` (это значение уже стоит в `wrangler.toml` —
поправить, если назовёте шаблон иначе), с переменными:

- `{{to_email}}` — куда слать (обязательно указать это же поле в EmailJS
  как адрес получателя в настройках шаблона "To Email");
- `{{code}}` — сам промокод;
- `{{amount}}` — сколько Старс даёт код;
- `{{price}}` — сумма оплаты в рублях;
- `{{pack}}` — купленный пакет (для справки в письме).

Текст письма — что-то вроде: "Спасибо за покупку! Ваш промокод: {{code}}.
Активируйте его в разделе Магазин → Донат на сайте, чтобы получить
{{amount}} Старс."

Затем в EmailJS: **Account → API Keys** — скопировать **Private Key**
(это и есть `EMAILJS_PRIVATE_KEY` из списка секретов ниже; он позволяет
слать письма не из браузера, без него EmailJS будет отклонять запросы
с сервера).

## DIY-оплата: настройка приёма SMS

1. Придумать длинную случайную строку — секрет для вебхука (например,
   сгенерировать в любом менеджере паролей). Она нужна, чтобы никто
   посторонний не мог слать Worker'у фальшивые "SMS" о зачислении.
2. На телефоне, куда приходят SMS/пуши от банка о поступлении денег,
   установить **MacroDroid** (Google Play, бесплатный тариф хватает).
3. Создать макрос:
   - **Триггер**: "SMS Received" (Получено SMS) — можно сразу указать
     отправителя (например, короткий номер банка, "900" у Сбербанка),
     чтобы макрос срабатывал только на банковские уведомления.
   - **Действие**: "HTTP Request" / "Web Request" — метод `POST`, URL:
     `https://<адрес-воркера>/sms-webhook?secret=<ваш секрет из шага 1>`,
     тело запроса (JSON): `{"text": "[магическая переменная текста SMS]"}`
     — в MacroDroid текст входящего SMS доступен как переменная триггера
     (в конструкторе строки — кнопка выбора переменной/"magic text",
     выбрать текст SMS из триггера "SMS Received"; точное название
     переменной может отличаться между версиями приложения).
   - Content-Type заголовок: `application/json`.
4. Протестировать: отправить самому себе SMS с текстом вида
   `Перевод 12.34р от теста` и проверить в `wrangler tail` (см. ниже),
   что запрос дошёл (даже если он не найдёт подходящий заказ — это
   нормально, главное убедиться, что сам вебхук вызывается).

Если предпочитаете другое приложение для пересылки SMS на вебхук (не
MacroDroid) — подойдёт любое, которое может сделать HTTP POST с текстом
SMS в теле запроса на указанный URL; секрет можно передавать и в самом
теле JSON, если приложение не поддерживает query-параметры в URL —
в этом случае нужно будет донастроить проверку секрета в
`worker/src/index.js` (`handleSmsWebhook`).

**Важно:** банк должен слать SMS о поступлении с суммой в тексте (у
Сбербанка это стандартно так). Если вместо SMS используются только
push-уведомления банковского приложения — их тоже можно пересылать тем
же способом (в MacroDroid есть триггер "Notification Received"), текст
пуша обычно похож по формату.

## Секреты — задать один раз после установки

```bash
wrangler secret put SMS_WEBHOOK_SECRET
wrangler secret put FIREBASE_CLIENT_EMAIL
wrangler secret put FIREBASE_PRIVATE_KEY
wrangler secret put EMAILJS_PRIVATE_KEY
```

- `SMS_WEBHOOK_SECRET` — придуманная в разделе выше строка.
- `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY` — из JSON-файла сервисного
  аккаунта Firebase: Console → Настройки проекта → Сервисные аккаунты →
  "Создать новый закрытый ключ" (скачается .json). Внутри файла — поля
  `client_email` и `private_key` (это длинный текст, начинается с
  `-----BEGIN PRIVATE KEY-----`, вставлять целиком, вместе с переносами строк).
- `EMAILJS_PRIVATE_KEY` — см. раздел про шаблон письма выше.

Также поправить в `wrangler.toml`:
- `PAYOUT_PHONE` — номер телефона, привязанный к СБП, куда переводить деньги;
- `PAYOUT_BANK_NAME` — банк-получатель (по умолчанию поставлен Сбербанк);
- `PAYOUT_RECEIVER_NAME` — имя получателя (как показывается в СБП-переводах).

(`ROBOKASSA_*` переменные и секреты не используются сейчас — трогать не нужно,
если провайдер не подключён.)

## Деплой

```bash
wrangler deploy
```

Выведет адрес вида `https://vat-payments.<ваш-поддомен>.workers.dev` — его
нужно вставить в `config/config.js` сайта как `PAYMENTS_WORKER_URL`
(сейчас там пусто, поэтому кнопка "Купить" в магазине показывает
заглушку "оплата скоро"), и туда же (без изменений) в шаге 3 настройки
MacroDroid выше.

## Проверка

```bash
wrangler tail
```

покажет логи в реальном времени — удобно смотреть при тестовой оплате,
проходит ли вебхук, находится ли заказ по сумме и уходит ли письмо.
