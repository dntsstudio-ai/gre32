# Бэкенд приёма платежей (Cloudflare Worker)

Один бесплатный "воркер" в облаке Cloudflare, который:
- по запросу с сайта создаёт ссылку на оплату Robokassa (цену пакета Старс
  берёт из своей же таблицы, а не из запроса — так её нельзя подделать);
  покупка НЕ требует входа в аккаунт — только почта покупателя;
- принимает от Robokassa подтверждение оплаты (ResultURL), проверяет подпись,
  создаёт одноразовый промокод в той же коллекции `promoCodes`, которую уже
  использует магазин на сайте (кнопка "Активировать промокод"), и отправляет
  этот код письмом на почту покупателя.

Начисление Старс никак не зависит от Robokassa напрямую — как только письмо
с кодом дошло, дальше работает существующая на сайте система промокодов.
Если платёжный провайдер поменяется, менять нужно будет только
`worker/src/robokassa.js` (или добавить рядом файл под новый провайдер) —
генерация кода и письмо останутся как есть.

## Разово: установка и вход

```bash
cd worker
npm install -g wrangler   # если ещё не установлен
wrangler login            # откроет браузер для входа в Cloudflare (бесплатный аккаунт подходит)
```

## Шаблон письма в EmailJS — создать один раз

В личном кабинете EmailJS (emailjs.com) создать новый шаблон, например с
id `template_starscode` (это значение уже стоит в `wrangler.toml` —
поправить, если назовёте шаблон иначе), с переменными:

- `{{to_email}}` — куда слать (обязательно указать это же поле в EmailJS
  как адрес получателя в настройках шаблона "To Email");
- `{{code}}` — сам промокод;
- `{{amount}}` — сколько Старс даёт код;
- `{{price}}` — сумма оплаты в рублях;
- `{{pack}}` — купленный пакет (для справки в письме).

Текст письма — что-то вроде: "Спасибо за покупку! Ваш промокод: {{code}}.
Активируйте его в разделе Магазин → Донат на сайте, чтобы получить
{{amount}} Старс."

Затем в EmailJS: **Account → API Keys** — скопировать **Private Key**
(это и есть `EMAILJS_PRIVATE_KEY` из списка секретов ниже; он позволяет
слать письма не из браузера, без него EmailJS будет отклонять запросы
с сервера).

## Секреты — задать один раз после установки

Это данные, которые нельзя хранить в репозитории. Для каждого — своя команда,
`wrangler` спросит значение в терминале:

```bash
wrangler secret put ROBOKASSA_PASSWORD1
wrangler secret put ROBOKASSA_PASSWORD2
wrangler secret put FIREBASE_CLIENT_EMAIL
wrangler secret put FIREBASE_PRIVATE_KEY
wrangler secret put EMAILJS_PRIVATE_KEY
```

- `ROBOKASSA_PASSWORD1` / `ROBOKASSA_PASSWORD2` — из личного кабинета
  Robokassa (Настройки → Технические настройки). **Внимание:** сейчас
  Robokassa отклонила заявку на подключение магазина — этот блок в коде
  оставлен как рабочий пример и заготовка на случай подключения через
  Robokassa (или похожий провайдер с такой же схемой подписи) в будущем;
  без реального подключённого провайдера ссылка на оплату будет вести на
  несуществующий магазин.
- `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY` — из JSON-файла сервисного
  аккаунта Firebase: Console → Настройки проекта → Сервисные аккаунты →
  "Создать новый закрытый ключ" (скачается .json). Внутри файла — поля
  `client_email` и `private_key` (это длинный текст, начинается с
  `-----BEGIN PRIVATE KEY-----`, вставлять целиком, вместе с переносами строк).
- `EMAILJS_PRIVATE_KEY` — см. раздел про шаблон письма выше.

Также поправить `ROBOKASSA_MERCHANT_LOGIN` в `wrangler.toml` (это не секрет,
просто логин магазина) и убрать `ROBOKASSA_TEST_MODE = "1"`, когда будете
готовы принимать настоящие платежи (в тестовом режиме Robokassa не списывает
реальные деньги).

## Деплой

```bash
wrangler deploy
```

Выведет адрес вида `https://vat-payments.<ваш-поддомен>.workers.dev`.

Его нужно:
1. Вставить в `config/config.js` сайта как `PAYMENTS_WORKER_URL` —
   тогда кнопка "Купить" в магазине будет обращаться именно к этому адресу.
2. Указать в личном кабинете Robokassa (когда/если магазин там подключат) как:
   - **ResultURL**: `https://.../robokassa/result`
   - **SuccessURL**: `https://.../robokassa/success`
   - **FailURL**: `https://.../robokassa/fail`

## Проверка

```bash
wrangler tail
```

покажет логи в реальном времени — удобно смотреть при тестовом платеже,
проходит ли подпись, создание промокода и отправка письма.
